## Genesis allocation and release

All 100M is minted at genesis. Unlocks are transfers/reclassifications, never issuance. Vesting uses integer base units and cumulative floor(total_locked * elapsed_periods / periods); the final tranche receives any remainder. First monthly tranche is on the cliff anniversary; there is no retroactive catch-up. Monthly dates are UTC calendar-month anniversaries.

Genesis minted, locked, unlocked, and custody are different categories. At genesis 5M is unlocked, but 2M is assumed ring-fenced as the reward reserve and 1M held for community distribution. Projected float is therefore at most 3M under those custody assumptions; unlocked is not equivalent to circulating. Treasury's 20M remains custodied and locked for float purposes. The 18M restricted reward allocation stays locked throughout the 48-month model because the prompt gives no release schedule. A later treasury transfer to the reward reserve changes funding/custody, not supply.

## Rewards, liabilities, and reserve sufficiency

For principal P in smallest units and integer elapsed 24-hour days D, reward = floor(P * 400 * D / 3,650,000). Each position snapshots principal, entry terms, maturity, base reward, and referral amount. Let F be funded reserve, R aggregate unclaimed reserved maximum, and C=500,000 SNX. Accept only if R+new_commitment <= C and <= F. Available capacity is min(C,F)-R. Claims reduce reserve assets and liabilities by the paid amount; cap headroom returns only after liability extinguishment. Independently, escrowed principal must always cover outstanding principal.

| Principal | 30-day base reward | 90-day | 180-day | 180-day plus optional 5% | Annual base outflow at 4% |
|---:|---:|---:|---:|---:|---:|
| 5M | 16,438.356164 | 49,315.068493 | 98,630.136986 | 103,561.643835 | 200,000 |
| 10M | 32,876.712329 | 98,630.136986 | 197,260.273973 | 207,123.287671 | 400,000 |
| 20M | 65,753.424658 | 197,260.273973 | 394,520.547945 | 414,246.575342 | 800,000 |

Values display rounded SNX; generated CSVs retain exact integer units. A single max-principal/180-day position is below the 500K cap, including optional referral. Concurrent positions can bind it: two 10M/180-day positions reserve about 394,521 SNX; three would require about 591,781 and the excess commitment must be rejected. At total principal 20M, mixes of 10M/180d + 10M/90d reserve about 295,890; 10M/180d + 10M/30d about 230,137. Linear reward arithmetic means splitting positions does not materially increase liability except base-unit rounding.

Low/base/high constant active principal is 5M/10M/20M. Annual base outflow is 200K/400K/800K SNX, respectively. With the initial 2M reserve and zero top-ups, gross runways are 10/5/2.5 years, assuming constant exposure, claims paid, no diversion/loss, and no other use. These are throughput ratios, not solvency guarantees. Entry reservation caps peak accepted unclaimed liability at 500K, while maturity clustering still matters: roughly 400K may mature together after a full 20M/180-day cohort. Repeating full utilization yields about 800K annual outflow. Delayed funding blocks new commitments; no accept-now/fund-later path is modeled. Simultaneous claims must update shared balances/liabilities atomically; transaction ordering is not a fairness policy. Principal has no assumed automatic rollover or top-up.

Zero referral is the base case. Optional single-level 5% additive referral increases each base liability by at most 5%, shares the same ceiling, and requires bounded eligibility, attribution, anti-cycle/Sybil rules and beneficiary approval. Alternatives for owner review: lower rate/shorter terms/lower exposure; no reward feature until treasury operations exist; or the optional referral. None is selected or approved.

## Reproduction

Run python scripts/v1_economic_model.py --output-dir docs/generated/v1-economic-model-check from the repository root. The script writes monthly allocation CSV, liability scenario CSV, and summary JSON in integer base units and refuses to overwrite a nonempty output directory. It reconciles all allocations to 100M and all scheduled tranches. The monthly projection does not model intramonth claims, actual wallets, market liquidity, price, adoption, legal enforceability, governance voting, arbitrary reserve loss, or deployment facts. It is a scenario calculation, not verified chain behavior or a commitment.
